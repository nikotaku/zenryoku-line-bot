# 店舗CTI (Store CTI)

店舗スタッフ向けの**社内専用** Android CTI補助アプリ。070/080/090・固定電話番号によるSIM回線の通常通話を使いながら、顧客情報の確認、通話後の対応記録、予約管理、SMS定型文の作成を1つのアプリで行えます。

- 日本語名: **店舗CTI** / 英語名: **Store CTI** / パッケージ: `com.store.cti`
- 配布: Google Play非公開。**署名付きAPKの直接インストール**(INSTALL_GUIDE.md 参照)
- 対応OS: Android 10 (API 29) 以上

## このアプリでできること

- 電話番号(ハイフン有無・+81表記の違いを吸収)による顧客検索・顧客管理(登録/編集/論理削除/区分/注意事項)
- 着信・通話後対応画面: 番号の手入力/貼り付け/共有メニュー受け取りで顧客を即表示、選択式中心の対応記録
- 発信: 番号入力済みの**標準電話アプリを開く**(`ACTION_DIAL`。発信操作はスタッフ)
- SMS: テンプレートから本文を自動生成し、宛先・本文入力済みの**標準SMSアプリを開く**(`ACTION_SENDTO`。送信操作はスタッフ)
- 予約の登録・一覧(本日/明日/日付指定/状態別/担当者別)・担当者/部屋の時間重複警告
- SMSテンプレート管理(追加/編集/並び替え/無効化、差し込み9項目)、SMS作成履歴
- CSV出力(顧客/予約/対応履歴/SMS作成履歴。UTF-8 BOM付き・Excel対応・CSVインジェクション対策済み)
- バックアップ(JSON)と復元(復元前警告+自動プリバックアップ)
- 設定: 店舗名/店舗電話番号/スタッフ/既定スタッフ/営業時間/予約枠標準時間/番号表示形式/マスク表示/スクリーンショット禁止/権限状態/監査ログ/データ初期化
- 実験機能(Phase 2): 通話スクリーニング役割による着信番号の顧客識別と通知(端末対応時のみ・明示的な有効化が必要)

## このアプリでできないこと(重要)

| できないこと | 理由・補足 |
|---|---|
| 携帯電話番号そのものの管理 | **070/080/090番号はSIM回線(通信会社)が管理**しています。本アプリは番号を発行・変更できません |
| 電話交換設備のような完全なCTI | MVPはPBX/クラウドPBXではありません。転送・保留・複数回線の制御はできません |
| SIM通話の自動録音 | Android 10以降、OS・端末・地域・通信会社レベルで制限されています。本アプリは録音機能を実装せず、「録音できる」と誤認させる表示もしません(将来連携用の`RecordingProvider`のみ用意) |
| 自動で電話に出る | 既定電話アプリ(InCallService)の権限が必要なため対象外(Phase 3として別開発) |
| 複数端末を同時に鳴らす | SIM回線はSIMを挿した1台でのみ着信します。実現には外部PBX/クラウド電話サービスが必要です |
| SMSの自動送信 | 本アプリは標準SMSアプリを開くまでを行い、**送信は必ずスタッフが操作**します。実際に送信されたかはアプリから確認できないため、履歴は「下書き作成/SMSアプリを起動/スタッフ確認済み」の3状態です |
| 着信番号の完全自動取得 | 端末・OSバージョン・権限状態により制限されます。MVPは手入力/貼り付け/共有を基本とし、Phase 2(通話スクリーニング)は対応端末でのみ動作します |

## 採用した前提(自律判断の記録)

開発中に発注者へ確認せず判断した内容の一覧です。

1. **ライブラリバージョン**: Kotlin 2.0.21 / AGP 8.7.3 / Gradle 8.10.2 / Room 2.6.1 / Hilt 2.52 / Compose BOM 2024.12.01 / compileSdk・targetSdk 35。開発環境から Google Maven(dl.google.com)のメタデータを照会できなかったため、「最新」よりも**相互互換性が確実に既知の安定組み合わせ**を優先した(docs/IMPLEMENTATION_PLAN.md 2章)。更新は `gradle/libs.versions.toml` の書き換えのみ。
2. **ビルド検証方法**: 同環境のネットワークポリシーで dl.google.com が遮断されていたため、Androidモジュールのビルド・テスト・APK生成は **GitHub Actions CI** で実施(`.github/workflows/android-ci.yml`)。純Kotlinの`:core`はローカルで検証済み。
3. **日時の保存形式**: RoomにはISO-8601文字列(`2026-07-20` / `14:00` / `2026-07-14T15:00`)で保存。文字列比較=時系列比較になり、バックアップJSONとの相互変換も単純になるため。
4. **重複電話番号**: 警告のみで保存は許可(家族が同じ番号を共有するケースがあるため)。
5. **予約の時間重複**: 警告のみで保存は許可(仕様書どおり)。判定はキャンセル/無断キャンセル/変更済み以外の予約が対象。
6. **debugビルドのapplicationIdサフィックスなし**: 静的ショートカットの`targetPackage`と一致させるため、debug/releaseとも `com.store.cti`。
7. **DB暗号化は初期版では追加しない**: Android 10+のファイルベース暗号化+内部ストレージ限定+allowBackup無効で代替(docs/SECURITY.md 4章に判断理由と代替措置)。
8. **顧客の来店実績**: 予約の「来店済み」変更による自動加算は行わず、顧客編集画面での手動管理(誤操作による二重カウント防止)。
9. **サンプルデータ投入ボタン**: `BuildConfig.DEBUG` ガードで debug ビルドのみ表示(データはすべて架空)。
10. **1店舗・複数スタッフ前提**: スタッフはデータ共有せず1台の端末内で完結(将来同期用に全データへUUID/syncStatus/versionを付与済み)。

## 権限とプライバシー

- 要求する危険権限: **なし**(Phase 2を有効化した場合のみ通知権限 `POST_NOTIFICATIONS`)
- `READ_CALL_LOG` / `WRITE_CALL_LOG` / `READ_SMS` / `SEND_SMS` / `CALL_PHONE` / `READ_PHONE_STATE` / `RECORD_AUDIO` は**マニフェストに存在しません**
- **Google Playで公開する場合**: SMS・通話履歴・電話関連の権限を使う構成に変更すると、Playの機微権限審査(Permissions Declaration)が必要になる可能性が高いです。現構成は審査対象権限を使っていません
- データはすべて端末内(アプリ専用領域)のみ。外部送信なし。詳細は docs/SECURITY.md と PRIVACY_POLICY_TEMPLATE.md

## インストール・アップデート・バックアップ

詳細手順は **INSTALL_GUIDE.md** を参照してください。要点:

- **インストール**: CI アーティファクトまたは `./gradlew :app:assembleDebug` で得た APK を端末へコピーし、「提供元不明のアプリ」を一時許可してインストール
- **アップデート**: 同じ署名の新しいAPKを上書きインストール(データは保持されます)。**署名が異なるAPKは上書きできません**(アンインストールするとデータが消えるため、必ず先にバックアップ)
- **バックアップ**: 設定 > バックアップを作成(JSON)。定期的に実行し、店舗PCなど管理された場所へ保管
- **復元**: 設定 > バックアップから復元(現在のデータは全置換。実行前に自動プリバックアップを内部に作成)

## 端末紛失時の対応

1. Google「[デバイスを探す](https://www.google.com/android/find)」で端末をロック → データ消去
2. アプリのデータは端末内のみのため、端末消去でアプリ内の顧客情報も消えます
3. 端末に画面ロック(PIN/生体)を必ず設定して運用してください(必須)
4. 端末内Downloads等にエクスポート済みCSV/バックアップを放置しない

## 既知の制限・端末依存問題

- **通話スクリーニング(Phase 2)**: RoleManagerの対応状況が端末メーカーで異なります。非対応端末では設定画面に「この端末では利用できません」と表示されます。一部メーカー(独自電話アプリ搭載端末)では役割を許可しても着信通知が出ないことがあります
- **SMSアプリ・電話アプリが無い端末**(タブレット等)では該当ボタンがエラーメッセージを表示します
- 共有メニューからの番号受け取りは、共有元アプリがテキストを共有できる場合のみ機能します
- `sms_body` エクストラの扱いはSMSアプリの実装依存です(ほとんどの標準アプリで動作しますが、本文が引き継がれない機種の報告があります)
- ホーム画面ショートカットのピン留め対応はランチャーアプリに依存します
- Android のクリップボードアクセス制限(Android 10+)により、バックグラウンドからの貼り付けはできません(アプリ内の「貼り付け」ボタンを使用)

## ビルド方法(開発者向け)

```bash
# 前提: JDK 17 / Android SDK (API 35) / ネットワークで Google Maven に到達できること
cd store-cti-android
./gradlew :core:test                 # 純Kotlinロジックの単体テスト(SDK不要)
./gradlew :app:testDebugUnitTest     # アプリ層の単体テスト
./gradlew :app:assembleDebug         # debug APK → app/build/outputs/apk/debug/
```

Android SDK に到達できない環境では `-Pcti.includeAndroid=false` を付けると `:core` のみで動作します。
