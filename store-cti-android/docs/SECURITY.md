# SECURITY.md — 店舗CTI 情報保護設計書

顧客の氏名・電話番号・接客メモという要配慮の個人情報を扱うため、以下を実装・運用方針とする。

## 1. 権限最小化

- 実行時に要求する危険権限: **なし**(MVP/Phase 1)
- Phase 2 有効化時のみ: `POST_NOTIFICATIONS`(API 33+、着信通知用)を**利用直前に説明ダイアログ付き**で要求
- CallScreening の役割(`ROLE_CALL_SCREENING`)はユーザーが設定画面で明示的にONにした場合のみ要求
- `READ_CALL_LOG` / `WRITE_CALL_LOG` / `READ_SMS` / `SEND_SMS` / `CALL_PHONE` / `READ_PHONE_STATE` /
  `RECORD_AUDIO` は宣言もしない(マニフェストに存在しない)
- 設定 >「権限状態」画面で現在の権限・役割の状態を確認可能

## 2. ログ

- 自前 `AppLogger` を経由。**リリースビルドは全ログ no-op**(`BuildConfig.DEBUG` 分岐)
- デバッグビルドでも電話番号は `PhoneNumberUtils.mask()`(中間4桁マスク)、氏名・メモは出力しない
- 例外はメッセージのみ記録し、スタックトレースに個人情報が乗る文字列連結をしない
- Crashレポートサービス(Firebase等)は**組み込まない**(外部送信を発生させない)

## 3. 保存領域

- Roomデータベース・DataStore・自動プリバックアップはすべて**アプリ内部ストレージ**
  (`/data/data/<pkg>/`)に保存。他アプリからは読めない(Androidのサンドボックス + FBE端末暗号化)
- `android:allowBackup="false"` — adb backup / Auto Backup 経由での吸い出しを禁止。
  バックアップは利用者が明示的に操作した場合のみ(SAFで保存先を自分で選ぶ)
- 外部ストレージへの直接書き込みはしない(SAF経由のみ)

## 4. データベース暗号化の検討結果

**MVPでは追加のDB暗号化を採用しない。** 判断理由:

- SQLCipher (Zetetic) は有力だが、ネイティブライブラリ追加(APK +数MB)と鍵管理設計
  (Android Keystore + 鍵ラップ)が必要で、鍵運用を誤ると復元不能事故につながる
- 旧 `androidx.security:security-crypto`(EncryptedFile/EncryptedSharedPreferences)は
  開発が停止(deprecated)しており新規採用しない
- Android 10以上の端末は**ファイルベース暗号化(FBE)が必須**であり、
  内部ストレージは端末ロックと連動して保護される。内部ストレージ限定運用 + allowBackup=false と
  組み合わせれば、MVPの脅威モデル(端末紛失・他アプリからのアクセス)に対して合理的な保護となる

**代替措置**: 内部ストレージ限定 / allowBackup=false / 画面ロック設定の運用必須化(INSTALL_GUIDE記載) /
マスク表示設定 / FLAG_SECURE設定 / データ初期化機能。
将来トレイに: SQLCipher + Android Keystore による鍵ラップ(ARCHITECTURE.md 将来課題)。

## 5. 画面上の保護

- 設定「電話番号をマスク表示」: 一覧・ホームで `090-****-5678` 形式表示
- 設定「スクリーンショットを禁止」: `WindowManager.LayoutParams.FLAG_SECURE` を有効化
  (スクリーンショット・画面録画・最近のタスク一覧のサムネイルを抑止)
- 注意顧客はラベル+アイコンで明示(誤対応防止も情報保護の一部)

## 6. エクスポート・バックアップ時の保護

- CSV出力・バックアップ実行前に**注意画面**(「個人情報を含むファイルを端末外に保存します。
  取り扱いに注意してください」)を表示し、明示的な確認後にのみ実行
- CSVインジェクション対策(`=` `+` `-` `@` 等で始まるセルの無害化)
- 復元時: 全置換の警告 + 自動プリバックアップ(内部ストレージ)を作成してから実行
- すべてのエクスポート/インポート操作を監査ログに記録(件数のみ。内容は記録しない)

## 7. 秘密情報の取り扱い

- ソースコードに秘密鍵・パスワード・APIキーを一切書かない(MVPは外部サービス連携なしのため該当なし)
- release署名鍵はリポジトリに含めない。`keystore.properties`(gitignore済み)から読む手順を
  INSTALL_GUIDE.md に記載

## 8. 監査ログ

- 作成/更新/論理削除/エクスポート/インポート/初期化/サンプル投入を `audit_logs` に追記
- detail には個人情報を含めない(対象UUID・件数のみ)
- 設定 >「デバッグ情報」から閲覧可能

## 9. 端末紛失時の対応(運用)

README / INSTALL_GUIDE に記載:

1. 端末に必ず画面ロック(PIN/生体)を設定して運用する(必須)
2. 紛失時は Google「デバイスを探す」でリモートロック → 消去
3. アプリ内データは内部ストレージのみのため、端末消去でアプリデータも消える
4. エクスポートしたCSV/バックアップファイルを端末内Downloads等に放置しない
5. 定期バックアップは店舗PCなど管理された場所へ移動して保管

## 10. 脅威モデル外(既知の限界)

- root化端末・端末ロック未設定端末では内部ストレージ保護が弱まる(運用で禁止)
- 標準SMSアプリへ渡した本文はSMSアプリ側の履歴に残る(SMS本文に過度な個人情報を書かない運用)
- SMS自体が平文通信である点はアプリでは制御不能(機微情報をSMSで送らない)
