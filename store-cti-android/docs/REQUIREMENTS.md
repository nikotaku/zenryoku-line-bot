# REQUIREMENTS.md — 店舗CTI (Store CTI) 要件定義書

作成日: 2026-07-14 / 対象バージョン: 0.1.0 (MVP)

## 1. 目的

店舗にかかってくる 070/080/090・固定電話番号による通常の携帯電話通話(SIM回線通話)を利用しながら、
店舗スタッフが以下を1つのAndroidアプリで一元管理できるようにする。

- 電話番号をもとにした顧客情報の即時確認
- 通話後の対応内容・予約内容・注意事項の記録
- 予約の登録・一覧・重複警告
- SMS定型文の自動生成と、標準SMSアプリを使ったスタッフ確認済み送信

Google Playでは一般公開せず、署名付きAPKを店舗スタッフのAndroid端末へ直接インストールして利用する。

## 2. スコープ定義

### 2.1 MVP(Phase 1)で実現すること

| # | 機能 | 実現方式 |
|---|------|---------|
| 1 | 顧客登録・編集・論理削除・検索(氏名/ふりがな/電話番号/顧客番号) | Room + 正規化番号カラム |
| 2 | 発信 | `ACTION_DIAL`(番号入力済みの標準電話アプリを開く。発信操作はスタッフ) |
| 3 | SMS作成 | `ACTION_SENDTO` + `smsto:`(宛先・本文入力済みの標準SMSアプリを開く。送信操作はスタッフ) |
| 4 | 着信対応 | 番号の手入力/貼り付け/共有受け取り(`ACTION_SEND` text/plain)で顧客検索 → 対応画面 |
| 5 | 通話後の対応履歴登録 | 選択式中心の入力フォーム |
| 6 | 予約登録・一覧・状態管理・重複警告 | Room + 純Kotlinの重複判定ロジック |
| 7 | SMSテンプレート管理・差し込み・SMS作成履歴 | Room + 純Kotlinテンプレートエンジン |
| 8 | 設定(店舗名/スタッフ/営業時間/表示形式/マスク表示/スクリーンショット制限 等) | DataStore |
| 9 | CSV出力(顧客/予約/対応履歴/SMS作成履歴、UTF-8 BOM、CSVインジェクション対策) | SAF (CreateDocument) |
| 10 | バックアップ(JSON)・復元(復元前警告+自動プリバックアップ) | SAF + kotlinx.serialization |
| 11 | 監査ログ・データ全削除(初期化) | Room |
| 12 | ホーム画面ショートカット(着信対応/クイックSMS) | 静的 shortcuts.xml |
| 13 | デバッグビルド限定のサンプルデータ投入 | BuildConfig.DEBUG ガード |

### 2.2 Phase 2(実験機能、機能フラグ付き)

- `RoleManager.ROLE_CALL_SCREENING` の役割要求(ユーザーが設定画面で明示的に有効化した場合のみ)
- `CallScreeningService` による着信番号の取得 → 顧客識別 → 通知表示(通知タップで対応画面へ)
- 端末非対応時は設定画面に「この端末では利用できません」と表示
- Phase 1 の動作を一切壊さない(役割未許可でも全機能が動作する)

### 2.3 Phase 3(本アプリでは実装しない。別開発として分離)

- `RoleManager.ROLE_DIALER` / `InCallService` による既定電話アプリ化
- 交換可能インターフェース(`DialerRoleGateway`)と設計資料のみ用意する
- 理由: 既定電話アプリは緊急通報・Bluetooth・イヤホン・複数SIM・保留・通話切替まで
  責任を負うため、中途半端な実装は通話不能などの重大事故につながる

### 2.4 実装しないこと(Androidの制限・方針による)

| 機能 | 理由 | 代替 |
|------|------|------|
| SIM通話の自動録音 | Android 10以降、サードパーティアプリによる通話音声録音はOS/端末/地域/通信会社レベルで制限。Google Playポリシーでも Accessibility 悪用等が禁止 | `RecordingProvider` インターフェースのみ設計。初期実装は `UnsupportedRecordingProvider`(「この構成では録音に対応していません」) |
| 着信番号の全自動取得(MVP) | `READ_CALL_LOG`/`READ_PHONE_STATE` はGoogle Play審査で制限されやすく、端末差も大きい | 手入力/貼り付け/共有/Phase 2のCallScreeningService |
| アプリからのSMS自動送信 | `SEND_SMS` は危険権限かつPlay審査対象。誤送信リスク | `ACTION_SENDTO` で標準SMSアプリを起動しスタッフが送信 |
| 自動で電話に出る機能 | InCallService(既定電話アプリ)が必須 | Phase 3 に分離 |
| 複数端末を同時に鳴らす機能 | 電話交換設備(PBX/クラウドPBX)の領域。SIM回線はSIMを持つ1台でのみ着信 | 将来の外部CTIサービス連携(README参照) |
| 通話履歴の読み書き | `READ_CALL_LOG`/`WRITE_CALL_LOG` は最も審査が厳しい権限群 | アプリ内の対応履歴で代替 |

## 3. 技術要件

- 言語: Kotlin 2.0.21 / 画面: Jetpack Compose (Material 3)
- 設計: MVVM + Repository + UseCase(責務分離)
- 非同期: Kotlin Coroutines / Flow
- DI: Hilt 2.52 / ローカル保存: Room 2.6.1 / 設定: DataStore Preferences
- 画面遷移: Navigation Compose / JSON: kotlinx.serialization / 日時: java.time
- ビルド: Gradle Kotlin DSL、AGP 8.7.3、Gradle 8.10.2、JDK 17(ビルド)
- minSdk 29 (Android 10) / compileSdk 35 / targetSdk 35
- テスト: JUnit4、純KotlinコアはJVMテスト
- 配布: 署名付きAPK(初期はdebug署名 + release署名手順書)

バージョン選定の根拠は README「採用した前提」参照。

## 4. 権限要件(最小権限)

| 権限 | 用途 | 種別 |
|------|------|------|
| (なし) | ACTION_DIAL / ACTION_SENDTO はインテントのみで権限不要 | - |
| `POST_NOTIFICATIONS` (API 33+) | Phase 2 の着信通知・クイック対応登録通知。利用直前に説明の上で要求 | 実行時 |
| `BIND_SCREENING_SERVICE` | CallScreeningService のシステムバインド用(サービス側宣言。アプリが要求する権限ではない) | サービス属性 |

`READ_CALL_LOG` / `WRITE_CALL_LOG` / `READ_SMS` / `SEND_SMS` / `CALL_PHONE` / `READ_PHONE_STATE` は**要求しない**。

## 5. 画面要件

以下 6-1〜6-10 は発注仕様書の番号に対応。

1. ホーム: 本日の予約件数/折り返し未完了件数/最近の顧客/主要機能への大ボタン導線
2. 顧客一覧: 氏名・ふりがな・電話番号(ハイフン無視)・顧客番号検索、最終利用日順/利用回数順、注意顧客絞り込み
3. 顧客登録・編集: 全項目保存、顧客区分6種、重複電話番号警告、論理削除
4. 顧客詳細: 基本情報+履歴(予約/通話対応/SMS)+操作ボタン(電話/SMS/予約登録/対応履歴追加/編集)
5. 着信・通話後対応: 番号貼り付け/手入力/共有受け取り、登録済みなら顧客カード(氏名・利用回数・前回利用日・前回担当・区分・注意事項・直近3件)を大きく表示、未登録なら新規登録導線、通話後入力フォーム(対応結果10種)
6. 予約一覧: 本日/明日/日付指定/状態別/担当者別、予約カード表示
7. 予約登録・編集: 全項目、状態6種、経路6種、担当者・部屋の時間重複警告
8. 対応履歴: 期間/番号/顧客名/スタッフ/結果/方向/折り返し未完了で絞り込み、関連顧客・予約へ遷移
9. SMSテンプレート: 登録/編集/並び替え/無効化、初期3テンプレート、差し込み9項目、送信前編集、作成履歴(下書き作成/SMSアプリを起動/スタッフ確認済み)
10. 設定: 店舗情報/スタッフ/営業時間/予約枠標準時間/番号表示形式/マスク表示/スクリーンショット制限/バックアップ/復元/CSV/テンプレート/アプリ情報/プライバシーポリシー/権限状態/デバッグ情報/データ初期化

## 6. データ要件

- 主要データは UUID / createdAt / updatedAt / deletedAt / syncStatus / version を保持(将来のサーバー同期用)
- 電話番号は displayPhoneNumber(表示用)と normalizedPhoneNumber(検索用、数字のみ・0始まり国内形式)を分離保存
- 削除は原則論理削除(deletedAt に日時を設定)
- 詳細は DATA_MODEL.md

## 7. 非機能要件

- 片手操作: 主要操作ボタンは画面下部配置
- 通話直後の入力は選択式中心
- 注意顧客は色+アイコン+ラベルで区別(色のみに依存しない)
- ライト/ダークモード両対応、フォントスケール拡大時にも崩れない(スクロール可能レイアウト)
- 電話番号・氏名・顧客メモをログに平文出力しない。リリースビルドでは詳細ログ無効
- 起動から顧客検索まで3タップ以内
